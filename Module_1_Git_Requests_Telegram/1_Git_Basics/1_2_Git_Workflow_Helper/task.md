# Завдання 1.2: Життєвий цикл Git та валідація повідомлень коммітів

У командній розробці існує стандарт **Conventional Commits** (загальноприйняті комміти).  
Повідомлення мають починатися з префікса типу змін:
* `feat:` — нова функціональність (feature)
* `fix:` — виправлення багу
* `docs:` — оновлення документації
* `refactor:` — переписування коду без зміни функціоналу

### 🎯 Ваше завдання:
Реалізуйте функцію `validate_commit_message(message: str) -> bool`:
1. Вона приймає рядок `message`.
2. Повертає `True`, якщо повідомлення починається з одного з допустимих префіксів: `"feat: "`, `"fix: "`, `"docs: "`, `"refactor: "`.
3. Додатково, довжина повідомлення після двокрапки повинна бути не менше 3 символів (наприклад `"feat: add login"` — валідне, а `"feat: a"` — ні).
4. Якщо префікс інший або опис занадто короткий — поверніть `False`.
